What Is Express.js?

History & Philosophy

Express was created by TJ Holowaychuk in 2010, inspired by Ruby's Sinatra. It is the de facto standard web framework for Node.js — minimalist by design, providing a thin layer of features without obscuring Node's own APIs.

Key Characteristics

  • Minimalist core — routing, middleware, and HTTP utilities only
  • Unopinionated — no prescribed project structure or ORM
  • Middleware-driven — everything is a function in the request pipeline
  • ~35M weekly npm downloads — most popular Node.js framework
  • Massive ecosystem — thousands of middleware packages available

Install & Quick Start

mkdir my-app && cd my-app
npm init -y
npm install express
const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('Hello Express!');
});

app.listen(3000, () => {
  console.log('Server running on :3000');
});

Built On Node's http Module

Express wraps Node's native http.createServer(), adding routing, middleware chaining, and a cleaner API — but you can still access the raw req and res objects underneath.

Routing — Methods, Paths, Parameters

HTTP Methods

app.get('/users',    handler); // Read
app.post('/users',   handler); // Create
app.put('/users/1',  handler); // Replace
app.patch('/users/1',handler); // Update
app.delete('/users/1',handler);// Delete

// Match ALL methods
app.all('/secret', requireAuth, handler);

Route Parameters

// Named parameters — captured in req.params
app.get('/users/:id', (req, res) => {
  console.log(req.params.id); // '42'
  res.send(`User ${req.params.id}`);
});

// Multiple params
app.get('/users/:userId/posts/:postId',
  (req, res) => {
    // req.params = { userId, postId }
  }
);

Query Strings

// GET /search?q=express&page=2
app.get('/search', (req, res) => {
  req.query.q;    // 'express'
  req.query.page; // '2' (always string)
});

Pattern Matching

// Regex in route paths
app.get(/.*fly$/, handler);
// matches butterfly, dragonfly

// Optional parameter (Express 5 style)
app.get('/users/:id?', handler);

// Route chaining with app.route()
app.route('/books')
  .get((req, res)  => { /* list */ })
  .post((req, res) => { /* create */ });

Multiple Handlers

// Array of handlers / middleware chain
app.get('/dashboard',
  authenticate,
  authorise('admin'),
  (req, res) => {
    res.render('dashboard');
  }
);

// Each handler can call next()
// to pass control to the next one

Middleware Fundamentals

The Middleware Signature

// Every middleware is a function with
// (req, res, next)
const logger = (req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next(); // pass to next middleware
};

app.use(logger);

If you don't call next(), the request hangs — no response is ever sent.

Order Matters

// Middleware executes top to bottom
app.use(express.json());     // 1st
app.use(cors());             // 2nd
app.use(helmet());           // 3rd
app.use('/api', authMiddleware); // 4th

app.get('/api/data', handler); // 5th

// Error handler must be LAST
app.use(errorHandler);        // 6th

Types of Middleware

TypeScope
Application-levelapp.use(fn) — runs on every request
Router-levelrouter.use(fn) — scoped to router
Route-levelInline: app.get(path, fn, handler)
Error-handling(err, req, res, next) — 4 args
Built-inexpress.json(), express.static()
Third-partycors(), helmet(), morgan()

Middleware Pipeline

Each middleware can modify req/res, end the cycle, or call next() to continue.

Built-in Middleware

express.json()

// Parses JSON request bodies
app.use(express.json());

// Options
app.use(express.json({
  limit: '10kb',      // max body size
  strict: true,       // only objects/arrays
  type: 'application/json'
}));

// POST { "name": "Ada" }
app.post('/api/users', (req, res) => {
  console.log(req.body.name); // 'Ada'
});

express.urlencoded()

// Parses URL-encoded form data
app.use(express.urlencoded({
  extended: true   // use qs library
}));

// <form method="POST">
//   <input name="email" value="a@b.com">
// </form>
app.post('/login', (req, res) => {
  console.log(req.body.email); // 'a@b.com'
});

express.static()

const path = require('path');

// Serve files from /public
app.use(express.static(
  path.join(__dirname, 'public')
));

// With virtual path prefix
app.use('/assets', express.static(
  path.join(__dirname, 'public')
));
// /assets/css/style.css → public/css/style.css

// Options
app.use(express.static('public', {
  maxAge: '1d',        // cache control
  index: 'index.html', // default file
  dotfiles: 'ignore'   // hide .files
}));

express.raw() & express.text()

// Parse body as Buffer
app.use('/webhook',
  express.raw({ type: 'application/octet-stream' })
);

// Parse body as plain text
app.use('/logs',
  express.text({ type: 'text/plain' })
);

Less common but useful for webhooks (Stripe, GitHub) and log ingestion endpoints.

Error Handling

Error Middleware Signature

// MUST have exactly 4 parameters
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(err.status || 500).json({
    error: err.message
  });
});

// Trigger with next(err)
app.get('/fail', (req, res, next) => {
  const err = new Error('Something broke');
  err.status = 500;
  next(err); // skips to error handler
});

Custom Error Classes

class AppError extends Error {
  constructor(message, status = 500) {
    super(message);
    this.status = status;
    this.isOperational = true;
  }
}

class NotFoundError extends AppError {
  constructor(resource = 'Resource') {
    super(`${resource} not found`, 404);
  }
}

// Usage in route
app.get('/users/:id', async (req, res, next) => {
  const user = await User.findById(req.params.id);
  if (!user) return next(new NotFoundError('User'));
  res.json(user);
});

Async Error Catching

// Express 4: wrap async handlers
const asyncHandler = (fn) =>
  (req, res, next) =>
    Promise.resolve(fn(req, res, next))
      .catch(next);

app.get('/users', asyncHandler(
  async (req, res) => {
    const users = await User.find();
    res.json(users);
    // Thrown errors auto-forwarded to
    // error middleware via .catch(next)
  }
));

// Express 5: automatic — no wrapper needed!
// Rejected promises are caught automatically

404 Handler

// Place AFTER all routes, BEFORE error handler
app.use((req, res, next) => {
  res.status(404).json({
    error: `Cannot ${req.method} ${req.path}`
  });
});

Tip: Layered Error Handling

Use operational errors (bad input, not found) for client-facing messages and programmer errors (bugs) for logging + generic 500. Never leak stack traces in production.

Static File Serving

express.static() Basics

const path = require('path');

// Serve from /public directory
app.use(express.static(
  path.join(__dirname, 'public')
));

// File structure:
// public/
//   css/style.css    → /css/style.css
//   js/app.js        → /js/app.js
//   images/logo.png  → /images/logo.png
//   index.html       → / (auto-served)

Virtual Path Prefix

// Files accessible under /static/*
app.use('/static', express.static(
  path.join(__dirname, 'public')
));

// public/css/style.css
//   → /static/css/style.css

// Multiple static directories
app.use(express.static('public'));
app.use(express.static('uploads'));
// Express searches in order declared

Caching & Performance Headers

app.use(express.static('public', {
  maxAge: '30d',          // Cache-Control
  etag: true,             // ETag header
  lastModified: true,     // Last-Modified
  immutable: true,        // immutable flag
  index: false,           // disable auto index
  dotfiles: 'ignore',     // hide .dotfiles
  redirect: false,        // no trailing / redirect
  fallthrough: true       // pass to next handler
}));

// Versioned assets for cache-busting
// /assets/style.abc123.css → maxAge: '1y'

Production Tips

  • Use a reverse proxy (Nginx, Cloudflare) for static files in production
  • Set long maxAge for versioned/hashed assets
  • Use compression middleware for dynamic responses
  • Serve static before session/auth middleware to avoid unnecessary processing
  • Consider a CDN for global distribution

Security Best Practices

Helmet — Security Headers

const helmet = require('helmet');
app.use(helmet());

// Sets 15+ HTTP headers:
// - Content-Security-Policy
// - X-Content-Type-Options: nosniff
// - X-Frame-Options: DENY
// - Strict-Transport-Security
// - X-XSS-Protection
// ...and more

// Customise individual headers
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", "cdn.example.com"]
    }
  }
}));

CORS Configuration

const cors = require('cors');

// Allow specific origin
app.use(cors({
  origin: 'https://myapp.com',
  methods: ['GET', 'POST'],
  credentials: true
}));

// Dynamic origin
app.use(cors({
  origin: (origin, cb) => {
    const allowed = ['https://a.com', 'https://b.com'];
    cb(null, allowed.includes(origin));
  }
}));

Rate Limiting

const rateLimit = require('express-rate-limit');

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100,
  message: { error: 'Too many requests' },
  standardHeaders: true,
  legacyHeaders: false
});

app.use('/api/', apiLimiter);

// Stricter for auth routes
const authLimiter = rateLimit({
  windowMs: 60 * 60 * 1000,
  max: 5
});
app.use('/auth/login', authLimiter);

Input Validation & CSRF

const { body, validationResult } = require(
  'express-validator'
);

app.post('/users',
  body('email').isEmail().normalizeEmail(),
  body('name').trim().notEmpty().escape(),
  (req, res) => {
    const errors = validationResult(req);
    if (!errors.isEmpty())
      return res.status(400).json(
        { errors: errors.array() }
      );
  }
);

Always validate and sanitise input. Never trust req.body, req.params, or req.query directly.

Separation of Concerns

  • app.js — Express config, middleware, mount routes
  • server.js — app.listen() only (testable app)
  • routes/ — URL mapping, input validation
  • controllers/ — handle req/res, call services
  • services/ — business logic, DB queries
  • models/ — data schemas (Mongoose, Sequelize)
  • middleware/ — reusable req/res transformations

Route → Controller → Service

// routes/users.js
router.get('/:id', userController.getById);

// controllers/userController.js
exports.getById = async (req, res, next) => {
  try {
    const user = await userService
      .findById(req.params.id);
    res.json(user);
  } catch (err) { next(err); }
};

// services/userService.js
exports.findById = (id) =>
  User.findById(id).lean();

Tip: Separate app from server

Export app from app.js and import it in server.js and in tests. This lets you run supertest(app) without starting a real server.

Express 5 — What's New

Automatic Promise Rejection Handling

// Express 4 — must wrap or use library
app.get('/data', async (req, res, next) => {
  try {
    const data = await fetchData();
    res.json(data);
  } catch (err) {
    next(err); // manual forwarding
  }
});

// Express 5 — just throw!
app.get('/data', async (req, res) => {
  const data = await fetchData();
  res.json(data);
  // Rejected promise → error middleware
  // automatically — no wrapper needed
});

Stricter Path Matching

// Express 4: loose, regex-like
app.get('/ab?cd', handler);
// matches /acd, /abcd

// Express 5: uses path-to-regexp v8
// — No optional characters with ?
// — Use {param} for optional segments
app.get('/users{/:id}', handler);
// matches /users and /users/42

// Wildcards use * syntax
app.get('/files/*path', handler);
// req.params.path = rest of URL

Removed / Changed APIs

Express 4Express 5
app.del()Removed — use app.delete()
req.hostRemoved — use req.hostname
req.param()Removed — use req.params / req.query
res.json(status, obj)Removed — chain .status().json()
res.send(status)Removed — use res.sendStatus()

Other Improvements

  • req.query now returns a getter (re-parsed on each access)
  • Brotli encoding support for res.sendFile()
  • res.render() returns a Promise when no callback given
  • Node 18+ required as minimum version

Install Express 5

npm install express@5

Express 5 reached stable release in 2024 after years in alpha/beta. Migration is straightforward for most apps — the biggest change is path matching syntax.

Complete Working Example

app.js — REST API + Views

const express = require('express');
const path = require('path');
const helmet = require('helmet');
const morgan = require('morgan');
const app = express();

// Config
app.set('view engine', 'ejs');
app.set('views', path.join(__dirname, 'views'));

// Middleware
app.use(helmet());
app.use(morgan('dev'));
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
app.use(express.static('public'));

app.locals.siteName = 'TaskBoard';
app.locals.year = new Date().getFullYear();

let tasks = [
  { id: 1, title: 'Learn Express',
    done: false },
  { id: 2, title: 'Build an API',
    done: true },
];
let nextId = 3;

// Views
app.get('/', (req, res) => {
  res.render('home', { title: 'Tasks', tasks });
});

// REST API
app.get('/api/tasks', (req, res) => {
  res.json(tasks);
});

app.post('/api/tasks', (req, res) => {
  const { title } = req.body;
  if (!title) return res.status(400)
    .json({ error: 'Title required' });
  const task = { id: nextId++, title, done: false };
  tasks.push(task);
  res.status(201).json(task);
});

app.patch('/api/tasks/:id', (req, res) => {
  const task = tasks.find(
    t => t.id === +req.params.id
  );
  if (!task) return res.status(404)
    .json({ error: 'Not found' });
  Object.assign(task, req.body);
  res.json(task);
});

app.delete('/api/tasks/:id', (req, res) => {
  tasks = tasks.filter(
    t => t.id !== +req.params.id
  );
  res.sendStatus(204);
});

Error Handling & Start

// 404 handler
app.use((req, res) => {

Summary & Next Steps

Core Takeaways

  • Express = minimal, middleware-driven web framework for Node.js
  • Routing maps HTTP methods + paths to handler functions
  • Middleware is the core pattern — everything flows through the pipeline
  • Built-in parsers for JSON, URL-encoded, and static files
  • Error handling uses the 4-argument (err, req, res, next) signature

Best Practices

  • Use express.Router() for modular route files
  • Apply security middleware (helmet, cors, rate-limit)
  • Always validate and sanitise user input
  • Separate app.js from server.js for testability
  • Use environment variables for config (dotenv)
  • Handle errors centrally with custom error classes
